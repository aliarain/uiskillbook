# Trace

Trace shows what an agent did before it answered: thinking time, searches, tool results, failures and the sources it used. Each row can open into output such as a code block, and summaries can nest further steps.

## Install

```bash
npx shadcn@4.18.0 add @siteplane/trace
```

Import it from `@/siteplane/components/trace`. The project needs Siteplane UI's one-time setup first: [installation](https://ui.siteplane.io/docs/installation/).

## When to pick it

- **vs [Marker](https://uiskillbook.com/skills/siteplane-marker):** Pick Marker for a single status line or note with no details to expand.
- **vs [Accordion](https://uiskillbook.com/skills/siteplane-accordion):** Pick Accordion for general expandable sections outside an agent transcript.

## Rules

- Build each row from a `TraceLine` with `TraceIcon`, `TraceTitle` and `TraceDescription`, wrapped in a `TraceCollapsibleTrigger` or a `TraceLink` to make it act.
- Set `status` to `running`, `error` or `pending`; leave it off for finished work.
- Put the state in the title words (present tense while running, past tense when done) since screen readers do not hear colour or shimmer.
- Ask for tool approval in an Alert after the Trace, not as a row.
- Pass `keepMounted` to `TraceCollapsibleContent` when a summary nests another Trace whose open state should survive.
